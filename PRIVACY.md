# ClawJS Privacy Notice

Last updated: 2026-05-18

This notice describes the privacy posture for the official ClawJS project. It
does not describe every third-party service a user may choose to connect.

## English

### Local-first default

ClawJS is designed so user data lives on the user's device or chosen local
workspace by default. The project does not require telemetry, analytics, crash
reporting, hosted accounts, or remote sync to use local framework features.

### Data that may be processed locally

Depending on enabled features, local data may include sessions, messages,
notes, files, tasks, contacts, calendars, memories, agent configs, audit logs,
search indexes, media metadata, provider references, connector metadata,
domain records, and sensitive records such as health, finance, legal,
education, employment, identity, security, billing, location, or family data.

### When data may leave the device

Data may leave the device only when the user or operator explicitly configures
or initiates an external flow, such as export/share, support diagnostics,
remote/sync, Relay, provider APIs, connectors, MCP tools, webhooks, OAuth,
hosted services, paid APIs, or publication workflows. These flows should be
approval-gated and documented by the feature that uses them.

### Support and diagnostics

Support data is manual opt-in. Users should redact private data before sharing
logs, screenshots, databases, workspaces, crash reports, or diagnostics.
Sensitive support exports should preserve labels showing domain, review
requirement, and disclaimer version where available.

### Third-party providers

If a user connects providers, APIs, models, stores, sync services, messaging
services, or other third parties, those providers may process data under their
own terms and privacy notices. The user chooses and controls those connections.

### Retention

Local records, indexes, logs, and audit data remain under the user's local
control unless the user configures external retention. Sensitive audit
retention should be local, configurable, and redacted by default.

### Minors and third parties

The official product is not directed to users under 18. Users should avoid
processing sensitive third-party data unless they have a lawful basis or
consent and should keep that data limited to what is necessary.

## Espanol

### Local-first por defecto

ClawJS esta disenado para que los datos del usuario vivan por defecto en el
dispositivo del usuario o en el workspace local elegido. El proyecto no exige
telemetria, analiticas, crash reporting, cuentas alojadas ni sync remoto para
usar funciones locales del framework.

### Datos que pueden procesarse localmente

Segun las funciones activadas, los datos locales pueden incluir sesiones,
mensajes, notas, archivos, tareas, contactos, calendarios, memorias,
configuracion de agentes, logs de auditoria, indices de busqueda, metadatos de
media, referencias a proveedores, metadatos de conectores, registros de
dominio y datos sensibles como salud, finanzas, legal, educacion, empleo,
identidad, seguridad, pagos, ubicacion o familia.

### Cuando pueden salir datos del dispositivo

Los datos pueden salir del dispositivo solo cuando el usuario u operador
configura o inicia explicitamente un flujo externo, como export/share, soporte,
diagnosticos, remoto/sync, Relay, APIs de proveedores, conectores, herramientas
MCP, webhooks, OAuth, servicios alojados, APIs de pago o publicaciones. Estos
flujos deben estar sujetos a aprobacion y documentados por la feature que los
usa.

### Soporte y diagnosticos

Los datos de soporte son opt-in manual. Los usuarios deben redactar datos
privados antes de compartir logs, capturas, bases de datos, workspaces, crash
reports o diagnosticos. Los exports sensibles deberian conservar etiquetas de
dominio, revision requerida y version de disclaimer cuando existan.

### Proveedores externos

Si un usuario conecta proveedores, APIs, modelos, stores, sync, mensajeria u
otros terceros, esos proveedores pueden tratar datos bajo sus propios terminos
y politicas de privacidad. El usuario elige y controla esas conexiones.

### Retencion

Los registros, indices, logs y auditoria locales quedan bajo control local del
usuario salvo que configure retencion externa. La retencion de auditoria
sensible debe ser local, configurable y redactada por defecto.

### Menores y terceros

El producto oficial no esta dirigido a menores de 18 anos. Los usuarios deben
evitar tratar datos sensibles de terceros salvo que tengan base legal o
consentimiento, y deben limitar esos datos a lo necesario.
